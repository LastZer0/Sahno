# صحنو — پروتوتایپ و پایهٔ فنی MVP

این مخزن شامل پروتوتایپ رابط خریدار/برگزارکننده/عملیات و پایهٔ فنی برای MVP فروش بلیت است. **تا زمان اتصال پروژهٔ اختصاصی صحنو و آزمون کامل تراکنش‌ها، هیچ بخشی از آن فروش زنده محسوب نمی‌شود.** نام هنرمند، سالن، تعداد فروش و اطلاعات مالی در حالت دمو نمونه‌اند؛ هیچ رویداد واقعی بدون مجوز و تأیید منتشر نشود.

## اجرا و بررسی

```bash
npm ci
npm run dev
npm run build
npm run test:sites
```

بدون متغیر محیطی، برنامه در حالت دمو اجرا می‌شود. وقتی `VITE_SUPABASE_URL` و `VITE_SUPABASE_PUBLISHABLE_KEY` برای پروژهٔ اختصاصی صحنو تنظیم شوند، فقط رابط خریدار متصل به دادهٔ واقعی نمایش داده می‌شود. در این حالت پنل برگزارکننده و عملیات نمایشی در دسترس نیستند و تا پیاده‌سازی مجوزهای واقعی نباید فعال شوند.

## انتشار روی Vercel

این مخزن در ریشهٔ خود Vite است. تنظیمات `vercel.json` خروجی `dist/client` و بازنویسی مسیرهای SPA را مشخص می‌کند. پس از اتصال مخزن GitHub به یک پروژهٔ **جدید و اختصاصی صحنو** در Vercel، هر push روی `main` می‌تواند انتشار خودکار بسازد؛ GitHub Actions مستقل از آن ساخت و آزمون را بررسی می‌کند. هیچ توکن Vercel یا Supabase نباید در فایل مخزن قرار گیرد.

متغیرهای عمومی سمت مرورگر در `.env.example` فهرست شده‌اند. کلید service role و شناسهٔ پذیرنده فقط در secrets سمت سرور Supabase قرار می‌گیرند. طرح `database/schema.sql` هنوز migration اعمال‌شده نیست. Edge Function بازگشت پرداخت باید بدون JWT قابل دسترس باشد؛ این تنظیم در `supabase/config.toml` آمده، ولی authority صرفاً پس از verify سروربه‌سرور معتبر است.

شرح معماری، مرز اعتماد، وضعیت فعلی و گیت‌های انتشار در `docs/MVP-architecture-fa.md` آمده‌اند.
