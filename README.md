# صحنو — پروتوتایپ و پایهٔ فنی MVP

این مخزن شامل پروتوتایپ رابط خریدار/برگزارکننده/عملیات و پایهٔ فنی برای MVP فروش بلیت است. **با وجود اتصال پایگاه دادهٔ اختصاصی، تا زمان آزمون کامل تراکنش‌ها هیچ بخشی فروش زنده محسوب نمی‌شود.** نام هنرمند، سالن، تعداد فروش و اطلاعات مالی در حالت دمو نمونه‌اند؛ هیچ رویداد واقعی بدون مجوز و تأیید منتشر نشود.

## اجرا و بررسی

```bash
npm ci
npm run dev
npm run build
npm run test:sites
```

بدون متغیر محیطی، صفحهٔ اصلی در حالت دمو اجرا می‌شود. مسیر `/mvp` فقط کاتالوگ منتشرشده را با کلید عمومی پروژهٔ اختصاصی صحنو می‌خواند؛ ورود و خرید در این مسیر غیرفعال است و تا زمان انتشار رویداد واقعی، فهرست خالی می‌ماند. وقتی `VITE_SUPABASE_URL` و `VITE_SUPABASE_PUBLISHABLE_KEY` در Vercel تنظیم شوند، صفحهٔ اصلی به رابط خریدار متصل تغییر می‌کند؛ **این متغیرها را قبل از آماده‌شدن درگاه، تست تراکنش‌ها و تأیید محتوای واقعی تنظیم نکنید.** پنل برگزارکننده و عملیات نمایشی در حالت متصل در دسترس نیستند.

## انتشار روی Vercel

این مخزن در ریشهٔ خود Vite است. تنظیمات `vercel.json` خروجی `dist/client` و بازنویسی مسیرهای SPA را مشخص می‌کند. پس از اتصال مخزن GitHub به یک پروژهٔ **جدید و اختصاصی صحنو** در Vercel، هر push روی `main` می‌تواند انتشار خودکار بسازد؛ GitHub Actions مستقل از آن ساخت و آزمون را بررسی می‌کند. هیچ توکن Vercel یا Supabase نباید در فایل مخزن قرار گیرد.

متغیرهای عمومی سمت مرورگر در `.env.example` فهرست شده‌اند. کلید publishable استفاده‌شده در `/mvp` عمومی است و تنها به دسترسی‌های RLS محدود می‌شود. کلید service role و شناسهٔ پذیرنده فقط در secrets سمت سرور Supabase قرار می‌گیرند. طرح `database/schema.sql`، هفت ایندکس تکمیلی و اصلاح مجوز کاتالوگ در سه migration روی پروژهٔ مستقل `Sahno` (`lblofaxdenfekxvrqnut`) اعمال شده‌اند؛ Edge Functionها هنوز مستقر نشده‌اند. Edge Function بازگشت پرداخت باید بدون JWT قابل دسترس باشد؛ این تنظیم در `supabase/config.toml` آمده، ولی authority صرفاً پس از verify سروربه‌سرور معتبر است.

شرح معماری، مرز اعتماد، وضعیت فعلی و گیت‌های انتشار در `docs/MVP-architecture-fa.md` آمده‌اند.
